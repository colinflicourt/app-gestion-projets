## Décisions (Claude, 2026-10-25)

1. **Une seule table de règles** : `JR_XP_REGLES` dans `serveur/lib/xp.php`, miroir `REGLES` dans `site/js/lib/xp.js`. Les fonctions pures prennent `$regles` en dernier paramètre (défaut `JR_XP_REGLES`) : les tests des règles passent une table de test fixe (celle du § 7), un seul test épingle les valeurs de `JR_XP_REGLES`. Changer le barème après la régulation ne touche donc qu'une constante, son miroir et ce test.
2. **Ordre** : le moteur pur (M1) vient avant la régulation (M2) parce que la simulation réutilise ses fonctions (SPEC § 18.10). Les missions serveur et iPhone (M3 à M5) attendent la validation de `REGULATION-XP.md` par Colin. Si Colin préfère, elles peuvent partir avant avec le barème actuel : rien n'y dépend des valeurs.
3. **Carte éclair** : création lue dans les 8 premiers caractères hexadécimaux de l'identifiant. Durée `quand − création < eclair_secondes` (600) → `carte_eclair` (5) sans bonus, **y compris une durée négative** (carte créée hors ligne puis terminée hors ligne : l'heure du geste précède la création chez Trello). Identifiant non Trello (carte locale pas encore créée) : le JS estime une carte éclair, le serveur recale.
4. **Échéance** : chaîne `iso_paris` de la copie. Heure locale `18:00` → comparaison au jour de Paris (`quand` le jour J ou avant) ; sinon `quand <= échéance` à la minute.
5. **Événements** : chacun porte `date` (le jour ou l'instant qu'il concerne) **et** `emis_le` (l'instant de l'action qui l'a déclenché) et une `cle` stable : `niveau:<domaine>:<n>`, `grade:<grade>`, `joker:<AAAA-MM-JJ>`. Un joker couvre hier mais n'est émis qu'aujourd'hui : l'iPhone trie et célèbre selon `emis_le`, jamais selon `date`.
6. **Réponse des écritures** : `xp_gagnee` et `domaine` sont calculés dans l'action et gardés dans `ecritures.resultat` (un renvoi rend les mêmes) ; l'objet `xp` est ajouté **à chaque réponse**, renvoi compris, par un troisième paramètre de `route_ecriture()`, donc toujours à jour. `xp_gagnee` d'un Annuler = − le gain de l'action annulée, lu dans le rejeu juste avant de l'annuler.
7. **Heure du geste** : `nouvelleEcriture()` pose `fait_le` (ISO UTC) sur l'écriture, envoyé à côté de `id_client`. Le serveur le garde pour `taches/cocher`, `taches/terminer`, `taches/deplacer` et `tirage/parti` s'il est lisible, dans les 7 derniers jours et au plus 2 minutes dans le futur ; sinon l'heure de réception.
8. **Gain affiché après Terminer et cocher** : toujours **estimé sur l'iPhone** par `xp.js` au moment du geste (le message part avant la réponse, en ligne comme hors ligne). Les totaux, niveaux et la série viennent du serveur (`reponse.xp`, puis `GET donnees`) ; hors ligne ils restent ceux de la dernière copie.
9. **Célébrations** : l'iPhone garde dans le magasin IndexedDB `donnees`, clé `celebrations`, `{ emis_le_max, cles: [...], total_vu }` (pas de nouveau magasin, pas de montée de version de la base locale). Un événement est à célébrer si `emis_le > emis_le_max` **et** sa `cle` n'est pas dans `cles` (un barème modifié peut redater un niveau déjà célébré). `cles` garde les niveaux et grades, et les jokers des 60 derniers jours. Rien en attente (`emis_le_max` absent) à la première ouverture : tout l'historique est en attente, donc récapitulatif.
10. **Simple ou récapitulatif** : 1 ou 2 événements en attente → célébrés l'un après l'autre (promotion d'abord, puis niveaux, puis joker) ; 3 ou plus → un seul récapitulatif, avec `+<total − total_vu> XP` (tout le total à la première ouverture) et les niveaux les plus hauts atteints par domaine.
11. **Export pour les régulations suivantes** : `GET xp/export` (session exigée) rend les actions non annulées `{id, type, domaine, carte_id, element_id, quand, source, precision_heure, urgent, echeance}`. Aucun titre n'existe dans `actions`, rien d'autre n'est exposé.
12. **Gain plafonné** (après la régulation) : l'iPhone estime 0 quand `xp.aujourdhui_paye` (plus ses propres gestes depuis la dernière réponse) atteint le plafond. Gain estimé à 0 : après Terminer, « Carte terminée. » sans la partie XP ; après une étape cochée, pas de « +5 XP ».
13. **Version** : `JR_VERSION = '0.4.1'`, `site/sw.js` `VERSION` recalculée, faux serveur e2e aligné (`tests/e2e/serveur.mjs` annonce encore `0.2.0`).

## Interfaces (contrats entre missions)

**M1, `serveur/lib/xp.php`** (pures, aucune base)
- `const JR_XP_REGLES = ['carte' => 30, 'bonus_urgent' => 20, 'bonus_echeance' => 10, 'carte_eclair' => 5, 'eclair_secondes' => 600, 'plafond_eclairs' => 2, 'etape' => 5, 'plafond_etapes' => 10, 'pas_niveau' => 160, 'grades' => ['stagiaire' => 0, 'assistant' => 1500, 'bras_droit' => 6000, 'majordome' => 22000]];` (barème C validé par Colin le 2026-10-25, plafonds ajoutés par M1b).
- `xp_creation_carte(string $carte_id): ?DateTimeImmutable` (null si l'identifiant n'est pas 24 caractères hexadécimaux).
- `xp_gain_carte(string $carte_id, array $donnees, DateTimeImmutable $quand, array $regles = JR_XP_REGLES): int`.
- `xp_seuil_niveau(int $n, array $regles = JR_XP_REGLES): int` (`pas/2 × n × (n − 1)`) ; `xp_progression(int $xp, array $regles = JR_XP_REGLES): array` → `{niveau, dans_niveau, taille_niveau}` ; `xp_grade(int $total, array $regles = JR_XP_REGLES): array` → `{grade, seuil, suivant: ?string, seuil_suivant: ?int}`.
- `xp_rejouer(array $actions, DateTimeImmutable $maintenant, array $regles = JR_XP_REGLES): array`. Entrée : `list<{id: int, type, domaine, carte_id, element_id: ?string, quand: DateTimeImmutable, donnees: array}>`, non annulées, triées par `quand` puis `id`. Sortie : `{total: int, domaines: array<domaine, int> (les 4 de JR_DOMAINES, 0 compris), gains: array<int id, int>, jours: list<'AAAA-MM-JJ'> (jours comptés, Paris), evenements: list<{cle, type: 'niveau'|'grade'|'joker', domaine?: string, niveau?: int, grade?: string, date: string, emis_le: string (ISO Paris)}>, serie: {jours: int, joker_libre: bool, dernier_joker: ?'AAAA-MM-JJ', en_jeu: bool}}`.
- `xp_objet(array $rejeu, array $regles = JR_XP_REGLES): array` → l'objet public `{total, grade, seuil_grade, grade_suivant: ?string, seuil_suivant: ?int, domaines: {<d>: {xp, niveau, dans_niveau, taille_niveau}}, serie: {jours, joker_libre, dernier_joker, en_jeu}, aujourdhui_paye: {etapes, eclairs}, evenements}` (événements : tous les niveaux et grades, les jokers dont `date` est dans les 30 derniers jours).

**M3, `serveur/lib/xp_donnees.php`** (base) et routes
- `xp_actions(): array` (actions non annulées au format d'entrée de `xp_rejouer`) ; `xp_etat(): array` → `xp_objet(xp_rejouer(xp_actions(), maintenant()))` ; `xp_gain_action(int $id): int` (0 si l'action n'est pas dans le rejeu) ; `heure_du_geste(mixed $fait_le): DateTimeImmutable` (décision 7).
- `route_ecriture(string $route, callable $action, ?callable $completer = null)` : `$completer(array $resultat): array` appliqué après `ecriture_unique`, renvoi compris. Les routes de `serveur/routes/taches.php` passent `fn(array $r): array => $r + ['xp' => xp_etat()]`.
- Résultats ajoutés : `tache_cocher`, `tache_terminer`, `tache_deplacer`, `tache_annuler` rendent en plus `xp_gagnee: int` et `domaine: string`. `tache_terminer` garde son `action` ; `tache_cocher` et `tache_deplacer` récupèrent l'identifiant rendu par `action_noter()` (0 XP si aucune action notée).

**API livrée par M3**
- `GET donnees` → réponse actuelle plus `xp` (forme `xp_objet`).
- `POST taches/cocher|terminer|deplacer|annuler` → réponse actuelle plus `xp_gagnee`, `domaine`, `xp`. Corps accepté en plus : `fait_le`.
- `GET xp/export` → `{ok, actions: [...]}` (décision 11).

**M4, `site/js/lib/xp.js`** (pures)
- `export const REGLES` (copie exacte de `JR_XP_REGLES`) ; `creationCarte(id): Date|null` ; `gainCarte({ id, urgent, echeance }, quand: Date, paye = { etapes: 0, eclairs: 0 }, regles = REGLES): number` ; `gainEtape(paye = { etapes: 0, eclairs: 0 }, regles = REGLES): number` (`paye` : `xp.aujourdhui_paye` plus les gestes faits depuis, décision 12) ; `seuilNiveau(n, regles)` ; `progression(xp, regles)` → `{ niveau, dansNiveau, tailleNiveau }`.
- `aCelebrer(evenements, vu)` → `{ mode: 'aucune' | 'simple' | 'recap', evenements }` (décisions 9 et 10) ; `marquerVus(vu, evenements, total)` → nouveau `vu`.

## Points à surveiller (Review Focus)

Chaque ligne a son test dans la mission indiquée.

1. **Joker émis après son jour** : joker couvrant mardi, émis mercredi après une promotion célébrée mardi soir → il est quand même célébré une fois. Test M1 (`emis_le` = heure de la première action comptée du mercredi) et M5.
